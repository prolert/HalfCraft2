# Копание сквозь стены Half-Life 2: дизайн прототипа

- Дата: 2026-10-17
- Ветка: `dig-prototype` (только локально, без push)
- Статус: черновик на проверку

## Цель

В мире Half-Life 2 можно ломать стены, пол и потолок карты, как блоки в Minecraft, и проходить в получившиеся
дыры: в туннели, прокопанные в камне за стенами карты, и насквозь в соседние комнаты. Это то, что SkyCraft
делает со Skyrim («Digging into Skyrim»), перенесённое на Source и официальный SDK (без исходников движка).

### Прототип готов, когда

1. ЛКМ по стене HL2 ломает кусок стены (клетку 1×1×1 блок) за время, которое ушло бы на блок её материала
   текущим инструментом, с обычными трещинами Minecraft; выпадает дроп этого блока.
2. Выкопанная клетка видна: стена HL2 в ней не рисуется, края дыры закрыты срезом стены.
3. По туннелю, прокопанному в стену и дальше в камень за картой, можно пройти; сквозь стену в соседнюю
   комнату тоже.
4. Соседнюю комнату видно через дыру с обеих сторон.
5. Дыры остаются после перезапуска обеих игр.
6. Вне дыр игра и картинка не изменились (сцены, NPC, освещение).
7. `make lint` и тесты Minecraft-мода проходят; оба движка собираются.

Проверка в игре идёт на движке `hl2dm` (64-bit) на карте `d1_trainstation_02`. Движок `hl2` (32-bit) должен
собираться, в игре его проверим после прототипа.

## Решения, принятые при обсуждении

| Вопрос | Решение |
|---|---|
| Что показать первым | И туннели в камне, и сквозные дыры в соседние комнаты |
| Как ломается стена | Как в Minecraft: время по материалу и инструменту, дроп блока |
| Сейвы HL2 | Дыры пока не откатываются при загрузке сейва; хранятся в мире Minecraft навсегда |
| Как вырезать дыру при отрисовке | Своя шейдерная DLL с копией шейдера стен: сначала подмена стокового шейдера по имени, затем переключение материалов на копию (`SetShader`); сначала короткая проверка (этап 1), запасной вариант: стоковые имена `.vcs` с обходным каналом данных |

## Не входит в прототип

- Пули, взгляд и движение NPC, физика пропов: для них стены в дырах остаются (трассы и физический мир движка не
  меняются).
- Рельеф (дисплейсменты), статические пропы, браш-сущности (двери, лифты, `func_brush`, `func_breakable`), небо:
  не копаются и не вырезаются.
- Откат дыр вместе с сейвами и «починка» карты новой игрой.
- Свет: лайтмапы запечены и через дыру не меняются; тени факелов могут не проходить сквозь дыру.
- Взрывы (TNT, гранаты) не копают стены HL2.
- Проверка в игре на движке `hl2`.

## Архитектура

Хозяин дыр — Minecraft. Выкопанные клетки хранятся в его мире; он решает, что можно копать, сколько ломать и
что выпадает. Source только показывает дыры и вырезает по ним свою геометрию.

```
Source server.dll ──кольцо коллизии──▶ Minecraft
   (треугольники и воксели стен + материал копания, флаг «целиком твёрдый»)

Minecraft: удар → клетка выкопана → соседи «вскрываются» → стенки дыры в меше секции
   (дыры в чанке мира, сохраняются с ним)

Minecraft ──кольцо рендера──▶ Source client.dll
   (kRenDug: маска секции; стенки дыры — в обычном kRenSection)

client.dll: маска → текстура → шейдер стен отбрасывает пиксели в дырах; r_novis
client.dll ──мост (как solids_since)──▶ server.dll
server.dll: вырезает выкопанные кубы из брашей в коллизии для Minecraft; дыры рядом с игроком в PVS
```

Клетка — это блок Minecraft (1 блок = 40 юнитов). Карты разнесены по слотам вдоль x (`map_slot`), поэтому
отдельный идентификатор мира для дыр не нужен: координаты клетки уже говорят, к какой карте она относится.

## Протокол (`protocol/schema`, затем `make proto`)

- `render.toml`: сообщение `kRenDug = 11`, полезная нагрузка `RenDug {sx, sy, sz, count}` + битовая маска
  512 байт (бит `x + 16z + 256y`), как у `kRenSolids`. `count = 0`: в секции ничего не выкопано, маска не
  передаётся. Отправляется после `kRenSection` секции и при каждом изменении её дыр; `kRenClearAll` сбрасывает
  и дыры.
- `collision.toml`, `ColTriFlags`: `kTriDiggable` (бит 2): треугольник браша мира, который можно копать;
  биты 8–15: `DigMaterial`.
- `collision.toml`, новое сообщение `kColVoid = 4` (уточнено при планировании, вместо флага `kColBlockSolid`):
  `ColRegion` (count = блоки с частичной пустотой) + `u8 kind[512]` (блок `bx + 8bz + 64by` региона:
  `kVoidNone = 0`, `kVoidAll = 1`, `kVoidSome = 2`) + `u64[8]` на каждый блок `kVoidSome` по порядку (бит
  `z*8 + x` слоя `y`: субвоксели снаружи карты, где нет браша мира). Уходит перед `kColRegion` региона, если в
  нём есть пустота. Почему не флаг: у блока в пустоте нет геометрии, а значит и `ColBlock`, к которому флаг
  можно прицепить; а для стенок дыры во внешних стенах карты (большинство стен HL2 граничат с пустотой) нужна
  пустота по субвокселям.
- Новый enum `DigMaterial` (u8): `kDigNone = 0, kDigStone, kDigStoneBricks, kDigIron, kDigPlanks, kDigDirt,
  kDigGlass`.
- `host_state.toml`, `HostFlags`: `kHostDigOff` (бит 4): `hc_dig 0`, новые клетки не копаются.

Хэш схемы уже не даёт связаться Minecraft и Half-Life, собранным из разных версий.

### Материалы

Тип поверхности HL2 (`surfacedata_t::game.material`, из `$surfaceprop` текстуры стороны браша) → `DigMaterial`:

| HL2 | Блок |
|---|---|
| `C` бетон | камень (`stone`, дроп булыжник) |
| `T` плитка | каменные кирпичи |
| `M` металл, `G` решётка, `V` вентиляция, `P` компьютер | железный блок |
| `W` дерево, `U` картон | дубовые доски |
| `D` земля | земля |
| `Y` стекло | стекло |
| всё остальное | камень |

## Сторона Minecraft (перенос из SkyCraft, MIT)

- **`world/HostDig.java`** (из `SkyDig.java`). Дыры по чанкам: вложение Fabric (`DugColumn` из списка
  `DugSection {sectionY, long[64]}`, без поля `world`), сохраняется с миром. На сервере: `open(pos, material)`
  отмечает клетку, роняет дроп блока материала (`Block.getDrops` с инструментом игрока), играет звук и
  частицы; вскрытие ставит блоки в соседние клетки. Без сетевых пакетов: клиент вызывает интегрированный сервер
  через `minecraft.getSingleplayerServer().execute(...)`, как уже делает `HostClient`.
- **`client/HostDigClient.java`** (из `SkyDigClient.java`) и миксин на `Minecraft.startAttack/continueAttack`
  (из `MinecraftDigMixin`). Удар: луч взгляда в пределах досягаемости находит треугольник Half-Life
  (`HostRay`/`HostClip`). Если он ближе ванильного блока и помечен `kTriDiggable`, клетка — та, в которой лежит
  поверхность (точка попадания, сдвинутая внутрь по нормали). Прогресс ломания и трещины идут как у блока
  материала с инструментом игрока. Когда клетка доломана, сервер её открывает. При `kHostDigOff` удар не
  копает.
- **Вскрытие.** Когда клетка выкопана, а также когда блок в выкопанной клетке исчезает по любой причине
  (игрок, TNT, поршень: это ловит `LevelChunkMixin`), каждая из 6 соседних клеток становится блоком и
  помечается выкопанной, если она не выкопана, пуста в Minecraft, её регион известен и она целиком «камень»
  (занятость брашами | пустота из `kColVoid` = все 512 субвокселей). Материал — камень, если пустоты в ней не
  меньше 256 субвокселей, иначе материал вскрывающей клетки. Так за стенами карты получается сплошной камень,
  а внутри толстой стены — её материал. Клетка, твёрдая лишь частично, блоком не становится: у неё остаётся
  поверхность Half-Life, а срез рисуют стенки дыры. Вскрытые блоки ставятся мимо журнала отката
  (`Rollback.untracked`): иначе загрузка сейва убрала бы их, а дыры остались бы, и туннель открылся бы в
  пустоту.
- **`client/render/DigWalls.java`** (из одноимённого файла SkyCraft, упрощённый). Для каждой грани выкопанной
  клетки, у которой сосед не выкопан, не закрыт непрозрачным блоком и не вскрыт, берётся слой 8×8 субвокселей
  соседа, прилегающий к грани («камень» соседа: занятость `HostCollision` | пустота `kColVoid`). Для твёрдых
  субвокселей рисуются квадраты на плоскости
  грани текстурой материала соседа: по `DigMaterial` треугольников Half-Life в соседней клетке, если их нет —
  камень. Дыра всегда закрыта, сквозь стену не просвечивает.
- **`WorldExporter`**: стенки дыры добавляются в меш секции (их рисует существующий рендерер блоков
  HalfCraft); после `kRenSection` уходит `kRenDug` секции.
- **Тесты (JUnit, рядом с существующими)**: биты секций и ключи; правило вскрытия (по маскам и флагам → какие
  соседи становятся блоками); грани стенок (дыры + маски соседей → ожидаемые квадраты); таблица материалов.

## Сторона Source: server.dll

- **Материалы** (`hc_world_collision.cpp`). Для стороны браша — трассой (уточнено при планировании: у
  server.dll нет системы материалов, а трасса даёт ту же поверхность, что пулям и шагам): луч из 1 юнита снаружи
  в 1 юнит внутрь центра грани, только мир; `surface.surfaceProps` попадания → `game.material` →
  `DigMaterial`. Кэш по номеру браша на карту; материал браша — самый частый у его сторон, по умолчанию камень.
  Треугольники брашей мира (модель 0, не небо, contents `SOLID | WINDOW | GRATE`) получают `kTriDiggable` и
  материал своей стороны; грани среза — материал браша. У дисплейсментов, пропов и сущностей флага нет.
- **Вырезание** (`core/hc_dig_clip.h`, чистая функция без SDK). Выпуклый кусок браша минус выкопанные кубы
  → выпуклые куски снаружи кубов (разрез по плоскостям куба, до 6 кусков на куб). Соседние выкопанные кубы
  сначала сливаются в боксы, как `Clip::Box` в SkyCraft. `WorldCollision::gather` вырезает так всё, кроме
  брашей неба. При изменении дыр `CollisionStreamer::invalidate` отправляет затронутые регионы заново.
- **Пустота за картой (`kColVoid`).** Дерево BSP карты (планы, узлы, листья, головной узел модели 0) читается
  из `.bsp` при загрузке карты (`core/hc_bsp_tree.h`). Точка — пустота, если её лист BSP твёрдый
  (`CONTENTS_SOLID`, туда входят листья снаружи карты) и она не внутри браша мира. Для каждого блока региона
  проверяются центр и 8 углов, сдвинутых внутрь на 1/16 блока: все 9 в пустоте — `kVoidAll`, ни одной —
  `kVoidNone`, иначе проверяются центры 512 субвокселей. Чистый код без вызовов движка, поэтому считается в
  рабочем потоке стримера.
- **Дыры с клиента**: `server/hc_dig.cpp` забирает изменения через мост `HalfCraft_DugSince` (как
  `HalfCraft_SolidsSince`, `shared/hc_bridge.h`).
- **PVS**: хук в `CBasePlayer::SetupVisibility` (`player.cpp`, уже в патче) добавляет `AddOriginToPVS` для
  выкопанных клеток в радиусе 24 блоков от игрока, сначала ближайших, не больше 64. Тогда NPC и предметы в
  соседней комнате приходят на клиент.
- **`hc_debug_voxels`**: выкопанные клетки при сверке считаются пустыми. **`hc_debug_dig 1`**: рисует
  выкопанные клетки и вырезанные куски брашей.

## Сторона Source: client.dll и шейдеры

- **`client/hc_dig.cpp/h`**: принимает `kRenDug` (через `blocks_on_message`), хранит дыры текущего слота
  карты (как `blocks_set_slot`), отдаёт их серверу через мост, держит маску для шейдера и `r_novis`.
- **Маска для шейдера**: область 128×128×64 блоков (x, z, y в Minecraft) вокруг игрока, привязанная к сетке
  секций. 64 слоя по 128×128 уложены плиткой 8×8 в одну процедурную 2D-текстуру 1024×1024 (1 байт на клетку,
  выборка без фильтрации), как атлас блоков. Перестраивается при изменении дыр и когда игрок уходит больше чем
  на 32 блока от центра области. Дыры вне области не вырезаются (за 64 блока по горизонтали).
- **Шейдерная DLL** `game_shader_generic_halfcraft.dll` (уточнено при планировании), собирается из проекта
  шейдерных DLL в SDK для hl2dm (`game_shader_generic_example_*.vpc`; в `vpc_scripts/projects.vgc` того же SDK
  прямо сказано, что мод может переопределять стоковые шейдеры). Код, скопированный у Valve, живёт в дереве SDK
  как новые файлы `materialsystem/stdshaders/hc_*` и попадает в `halfcraft-hl2dm.patch` через `make patches`,
  как уже сделанные правки шейдеров фонарика. Внутри — копия `LightmappedGeneric`: только пиксельный шейдер
  2.0b с `clip` (стоковый вершинный шейдер без изменений) и проход факелов с тем же `clip`. Пиксель берётся на
  полюнита глубже поверхности по лучу взгляда (поверхность принадлежит клетке за ней, как в
  `HostRay.surfaceCell`). Маску и её угол шейдер берёт у client.dll через экспорт `HalfCraft_DigMask`
  (сэмплер `s15`, константы `c20`/`c21`).
- **Как шейдер попадает на стены** (решает этап 1): вариант A — DLL регистрирует шейдер под именем
  `LightmappedGeneric`, и движок берёт его вместо стокового; материалы не трогаются. Вариант B — DLL
  регистрирует `HC_LightmappedGeneric`, а client.dll при загрузке карты проходит по материалам из texdata
  `.bsp` и ставит `IMaterial::SetShader("HC_LightmappedGeneric")` тем, у кого `LightmappedGeneric`; материалы
  брашей с другими шейдерами пишутся в лог один раз за карту. Вариант C — стоковые имена `.vcs` с обходным
  каналом данных — потребует нового плана. Шейдер работает при любом `hc_dig`: `hc_dig 0` только запрещает
  копать новые клетки, уже выкопанные остаются вырезанными.
- **hl2 (32-bit)** в прототипе остаётся без шейдерной DLL: у дерева SDK 2015 года нет ни ShaderCompile2, ни
  `flashlight_ps2x.fxc`. client.dll, не найдя DLL, выключает копание (`kHostDigOff`) и один раз пишет об этом в
  лог.
- **Видимость**: пока у текущей карты есть дыры, client.dll включает `r_novis 1` и `r_portalsopenall 1` (флаг
  чита снимается) и возвращает прежние значения на карте без дыр. Стоимость в FPS замеряется на этапе 6
  (`hc_perf`).
- **Сборка**: `tools/halfcraft/shaders.py` и `build.py` сначала компилируют `hc_*.fxc` (их `.inc` нужны C++), потом
  собирают DLL для hl2dm; `make build` кладёт DLL рядом с client.dll в `build/game-hl2dm`, а `.vcs` — в
  `shaders/fxc`.

## Порядок работ

0. **Окружение.** Поставить GNU make (`winget install ezwinports.make`), Python 3.13, а для `make lint` и
   `make tidy` ещё clang-format и clang-tidy 22 и ruff; `make setup`, `make build`; убедиться, что нетронутый HalfCraft запускается на `hl2dm` (`make mc-run`,
   `make run MAP=d1_trainstation_02`).
1. **Проверка подхода (код на выброс).** Шейдерная DLL с копией `LightmappedGeneric`, которая вырезает заданный
   в коде бокс в стене у старта карты: сначала вариант A (подмена по имени), если движок её не берёт — вариант B
   (`HC_LightmappedGeneric` + `SetShader`). Ответить на вопросы:
   - вне бокса картинка совпадает со стоковой (скриншоты до и после, сравнение по пикселям);
   - бокс вырезан, свет факелов на стенах работает;
   - с `r_novis 1` / `r_portalsopenall 1` через бокс видно соседнюю комнату;
   - листья снаружи карты в `.bsp` твёрдые;
   - игрок, вошедший внутрь браша, там остаётся: физическая тень игрока (`VPhysicsShadowUpdate`) не
     вытаскивает его обратно (для этого бокс в том же коде на выброс вырезается и из коллизии, которую
     `WorldCollision::gather` отдаёт Minecraft);
   - откуда движок hl2dm загружает DLL (`bin/x64` или `bin`), и что `hl2` (32-bit) работает без неё.

   Если не работают ни подмена по имени, ни `SetShader`, переходим к запасному варианту (стоковые имена `.vcs`
   с обходным каналом данных), пишем для него новый план и обновляем этот документ.
2. **Протокол**: изменения схемы, `make proto`.
3. **Minecraft**: `HostDig`, `HostDigClient` с миксином, вскрытие, `DigWalls`, экспорт `kRenDug`, тесты.
4. **server.dll**: материалы в коллизии, `hc_dig_clip.h`, пустота `kColVoid`, мост, инвалидация регионов, PVS,
   отладочные команды.
5. **client.dll**: приём `kRenDug`, маска, настоящий `HC_LightmappedGeneric`, переключение материалов,
   `r_novis`, `hc_dig`.
6. **Проверка в игре** (ниже).

## Проверка

- **Юнит-тесты Minecraft** (`make mc`: gradle build вместе с тестами): см. раздел Minecraft.
- **Сборка и линтеры**: `make build` (оба движка), `make lint`, `make tidy`.
- **В игре** на `d1_trainstation_02`, в тестовой сессии (`make test-start`, `make mc-test`), скриптом через
  `hc_look`, `hc_press`, `hc_key`, `hc_mc`, `tools/game/wait_log.py` и скриншоты:
  1. копнуть клетку стены: в логе `kRenDug`, на скриншоте дыра с краями, выпал дроп;
  2. прокопать 3 клетки в стену и дальше в камень, войти (`hc_key` W), проверить позицию игрока по логу;
  3. пробить стену в соседнюю комнату, пройти в неё, сделать скриншоты через дыру с обеих сторон;
  4. закрыть обе игры, запустить снова: дыры на месте;
  5. скриншот нетронутого места до переключения материалов и после: совпадает;
  6. `hc_perf` с дырами и без: FPS записывается в отчёт.

## Риски и запасные варианты

| Риск | Что делаем |
|---|---|
| Движок не берёт подменённый по имени `LightmappedGeneric`, а `SetShader` ломает лайтмапы, кубмапы или не применяется к материалам мира | Этап 1 это показывает; запасной вариант — стоковые имена `.vcs` с обходным каналом и новый план |
| Компиляция комбинаций `LightmappedGeneric` идёт долго | Собирать только нужные для DX9 комбинации, как уже делает `shaders.py` |
| `r_novis` сильно роняет FPS | Включать только пока игрок рядом с дырой, ведущей в другую область |
| Физическая тень вытаскивает игрока из браша | Этап 1; если так, выключить столкновения тени с миром внутри выкопанных клеток |
| Срез стенки рисуется и по пропам и дисплейсментам в соседней клетке (маска их не различает) | Известный артефакт прототипа |
| Можно выкопаться за пределы задуманного и обойти триггеры сценария | Так задумано; `hc_dig 0` выключает копание |
| Дыры не откатываются сейвами | Принято для прототипа |
